# Verification Platform implementation plan

Planning baseline: 2026-10-07. This document sequences the approved architecture; it delivers no implementation, installation, release, or project adoption.

## Authority and execution scope

Read these authorities before implementing a slice:

- [Platform architecture](../verification-platform.md): product ownership, contracts, shared implementation, sole WSL → Windows topology, evidence/verdict semantics, and one release/distribution.
- [SpecKit integration](../verification-platform-speckit-integration.md): downstream process ownership, creation and freshness of proof plans, existing gates, handoff, and governed consumption.
- [Host-runtime evidence](../verification-platform-host-runtime-experiment.md): established PASS for owned Node-client exit, clean relay teardown, attached-relay termination, and fresh reconnect against the same caller-owned Chrome incarnation. Reuse this evidence within its stated limits.

The platform implementation belongs in the dedicated `ahhakopian/verification-platform` repository, intended to be checked out at `~/tools/verification-platform/`. `~/tools/` is only a local parent directory of independently versioned repositories. SpecKit changes belong in the existing governance/overlay repositories listed below, even where those repositories are adjacent directories in this workspace. Application providers, consumer configuration, normative feature plans, generated tests, and execution evidence belong to consuming projects. No application instrumentation is authorized by this plan.

There are six implementation slices. Their numbers express the main dependency path, not a requirement to postpone independent downstream work. In particular, implement SpecKit planning/gate integration as soon as slice 1 contracts stabilize, and its execution handoff after slice 3. Slice 5 finishes that work; it does not start it. Generic-only integration need not wait for slice 4's optional capabilities.

Preserve these architectural constraints throughout implementation: ordinary `@playwright/test`, one Playwright/CDP driver, one shared support library, explicit provider imports, no interpreted action language or workflow engine, no implicit environment/focus/native fallback, no automatic installation or retry, and no platform dependency on SpecKit. Missing normative behavior returns to its owner. A direct implementation blocker is recorded and stops only its dependent work; it does not authorize redesign.

## Contract milestones and dependency path

Freeze the small public contracts before dependent implementation, with representative serialized fixtures and consumer import/type checks. This means downstream code can target those contracts; it does not falsely advertise an unimplemented capability or unpublished release.

| Contract | Stable milestone | Downstream work enabled |
| --- | --- | --- |
| Neutral binding, resource-index formats and resource resolution | Slice 1 | Exact immutable selection; offline planning; SpecKit fingerprint inputs and resource-validation calls. |
| `browser-verification-plan.json` schema and structural validator | Slice 1 | All producers/gates/compiler use one schema/validator; adapter planning, approval and task checks begin immediately. |
| Provider/capability/readiness contracts | Slice 1; prove real exported composition in slice 2 | Honest planning capability dispositions and project-provider declarations; no provider implementation required at development-readiness gates. |
| Shared runtime API | Types and ownership/error contracts in slice 1; usable fixture/host/CDP/native entries in slice 2 | Consumer fixture composition and downstream execution configuration; later capability extensions remain additive. |
| Evidence/result and coverage-manifest contracts | Formats, identity keys, and verdict rules in slice 1; executable evidence/reconciler/reporter in slice 2 | Adapter result-consumption tests can start against contract fixtures in slice 1 and integrate real reports in slice 2. |
| Orchestrator invocation/return contract | Slice 1; usable compiler frontend in slice 3 | Adapter handoff implementation starts before the compiler exists, then tests real invocation in slice 3. No transient handoff registry. |

The complete path is:

```text
slice 1: valid plan + digest-checked resolved binding + authorized assignment
    → slice 3: verification-orchestrator discovers actual exports and maps claims
    → slice 3: generated ordinary .spec.ts + complete coverage manifest + typecheck
    → slice 2: shared fixtures/runtime and ordinary Playwright Test in WSL
    → slice 2/4: assigned Windows Chrome/CDP and supported native UIA
    → slice 2: flushed evidence + one reconciliation implementation
    → PASS | FAIL | BLOCKED | INCONCLUSIVE, preserving runner status
    → slice 5: SpecKit consumes current identities/evidence through existing gates
```

Slice 2 establishes a runnable plan-bound deterministic reference scenario and result path. Slice 3 establishes the first complete **orchestrator-generated** end-to-end path. Neither requires every optional capability in slice 4. Installed/governed consumer operation additionally requires an actual matching distribution/release and explicit project binding; the release-support work starts in slice 1 and completes in slice 6. Test-only synthetic index/release fixtures never authorize a real consumer run or substitute for a published pin.

## Slice 2 — Shared runtime and deterministic evidence path

**Goal:** Run an ordinary plan-bound Playwright reference test in WSL against explicitly assigned Windows Chrome, through migrated shared helpers, and produce a complete four-verdict result. This is the smallest executable vertical slice.

Extend distribution assembly to include compiled entries, declarations, CJS, Python/PowerShell/shell assets and required frontend content.

Choose and exactly pin a compatible `@playwright/test`/API dependency set and build dependencies using the accepted baseline; verify CJS-to-TypeScript interoperation and reporter APIs against that set. Do not install a replacement API silently or re-audit unrelated runner features. If the matching runner cannot be obtained or used, record a concrete dependency blocker. Consumer setup remains an explicit ordinary task, not work performed automatically during verification.

The worker fixture acquires/revalidates the assigned runtime via the existing helper, waits for its readiness JSON, retains owned handles, and uses `chromium.connectOverCDP()` on its current endpoint. Select the assigned borrowed context/page by explicit criteria. Never use Playwright's default launch/isolated-context fixtures. Configure one worker, no full parallelism, zero retries and exclusive caller assignment for a shared browser/native desktop. Replacement workers acquire fresh incarnations/connections. Test fixtures own temporary CDP sessions, observers, handles and permitted disposable pages; borrowed browser/profile/pages remain caller-owned.

Implement host deadlines/cancellation, bounded idempotent disposal and failure categories. Retain stdout/stderr/exit facts and native/extension raw errors. Readiness is bounded and non-destructive: verify prerequisites/support without probing actions. Native typed calls use the same script, exact criteria and fresh runtime validation. A timeout after a possible native action records uncertainty, never an automatic repeated action. Unexpected connection loss invalidates observers/handles; no hidden retry or replay.

Implement evidence as records flushed to `testInfo.outputPath()` and attached through ordinary Playwright APIs. Record attempt start before the relevant action, source facts/identity/windows/loss, and per-claim completion only after required assertions and evidence. Failure-safe recording preserves a decisive contradiction before rethrowing its assertion error. Arbitrary exceptions are unresolved. Opaque handles stay in memory. Evidence includes real provenance and namespaced identities; wall clocks across hosts are not a common ordering authority.

Implement one reconciler for manifest/assignment coverage, identities, claim/evidence records and runner/collection/cleanup limitations. Reporter and crash finalizer call it. Cover required blocked entries even with no runnable tests; preserve filtered/skipped/serially prevented entries and zero-test coverage. Reuse prior evidence only under checked validity conditions. Aggregation is FAIL, else BLOCKED, else INCONCLUSIVE, else PASS. Cleanup affects the existing claim only as defined by its accepted proof/behavior; retain other cleanup errors separately. The invocation adapter calls ordinary Playwright, preserves its original exit/status and yields acceptance exit zero only for complete PASS. It supplies crash/no-test finalization from flushed files, without becoming another runner.

**Existing implementation reused:** All five scripts and existing tests listed above; existing host discovery/relay behavior and established teardown/reconnect evidence. Ordinary Playwright performs assertions, steps, fixtures, execution, attachments and reports. Thin adapters add types/lifetime/evidence rather than rewriting automation.

**Earlier dependencies:** Slice 1 contracts and indexed-resource validation. The reference test/manifest is a checked compilation fixture, not yet the AI orchestrator.

**Tests/checks:** Run migrated mock/synthetic regression suites and focused adapter/ownership tests. Use deterministic fixture records to prove the four verdicts, decisive assertion versus infrastructure error, attempt-state uncertainty, complete claim/environment coverage, provider/identity mismatch, crash finalization, missing attachments and proof-relevant cleanup. Exercise pinned TypeScript imports/CJS/fixtures/reporter with ordinary Playwright. One bounded assigned Windows smoke proves attach → explicit observation/assertion → attachment → reconciled result, plus supported native inspection if assigned. Reuse host-lifecycle PASS evidence; do not repeat relay teardown/reconnect experiments. Resolve only the selected connection-disposal API and native-cancellation deltas described in the empirical table.

**Completion criteria:** The same canonical helper code is imported by deterministic adapters and accessible to agent compatibility entries. A valid reference plan and manifest run through ordinary Playwright against assigned Windows Chrome and return identity-bound result JSON and attachments. The report accounts for every required claim/environment, and invocation exit semantics match aggregate verdict. Unsupported capability/prerequisite entries remain explicit.
